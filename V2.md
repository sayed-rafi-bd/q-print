# Plan: API data source for label templates

Status: **Phases 0, 1 and 2 are done; Phases 3 to 5 are still to do.** See the progress column in section 8. Branch: `develop` (after the Biome cleanup).

## 1. Goal

A label template can declare a **URL pattern** with variables, for example:

```
api.github.com/day/{day}/count/{count}/logs
```

At print time:

1. The user types a value for each variable (`day`, `count`), and optionally a bearer token.
2. The app builds the URL, calls the API, and reads the JSON response.
3. The response becomes the page data:
    - **Object** response: one record.
    - **Array** response: one record per item.
4. Each record is printed `Number of pages` times (the existing page-count field is kept). Total pages = `records × copies`.

Print order is grouped by record: item 1 × n, then item 2 × n, and so on, so copies of a label come out together.

### Decisions already made

| Topic | Decision |
|---|---|
| Copies | Every record is printed `Number of pages` times. |
| Auth | Optional bearer token. A designer toggle turns it on for a template. |
| Token storage | The token is entered at print time and is **never** saved in the database or in exported label files. |

### Assumptions (change if wrong)

- GET requests only, JSON responses only.
- Variable values are URL-encoded when substituted (`2026/10/15` becomes `2026%2F10%2F15`).
- Fields that have no `api` rule keep working exactly as today (random, table, sequence, and so on), and can be mixed with `api` fields on the same label.
- Copies of the same record share their API values, but other rules (e.g. `digits`) still generate fresh values per page, as they do now.
- A response path that is missing from a record is an error that names the field, the path and the record number. A `null` value prints as empty text.

## 3. Data model

### 3.1 `spec.ts` additions (all optional, so old labels keep working)

```ts
/** Where record data comes from. Lives in the label, so it is saved and exported with it. */
export type ApiSource = {
  /** Pattern with {variables}. Scheme optional: "api.example.com/x" means https. */
  url: string;
  /** Optional: where the list lives in the response, e.g. "data.items". Empty = the root. */
  listPath?: string;
  /** Send "Authorization: Bearer <token>". The token itself is never stored here. */
  bearerAuth?: boolean;
  /** Optional nicer labels / default values for the variables the URL declares. */
  variables?: Record<string, { label?: string; default?: string }>;
};

export type GeneratorSpec = {
  version: 1;
  tables?: Record<string, GeneratorTable>;
  source?: ApiSource;               // NEW
  fields: Record<string, FieldRule>;
};

// NEW rule kind (also add 'api' to RULE_KINDS):
| { kind: 'api'; path: string }     // "user.name", "items[0].id", "total"
```

The existing `prefix`, `suffix` and `transforms` apply to `api` values too (they are in `Common`), so for example `yen` style prefixes still work.

`path` syntax: dot-separated keys plus `[n]` array indexes. The path is relative to the record (the object, or the array item).

### 3.2 Value conversion

| JSON value | Printed as |
|---|---|
| string | as is |
| number, boolean | `String(value)` |
| `null` | empty string |
| missing key | error (names field, path, record number) |
| object / array | error: "path points at an object; pick a field inside it" |

### 3.3 Variables

- Variables are read from the URL: `{name}` where `name` matches `[A-Za-z_][A-Za-z0-9_]*`.
- They do not clash with the pattern-rule tokens (`{d12}`, `{from}`): those live in field rules, not in the URL.
- The same variable used twice in the URL is asked for once.

## 4. Pure logic (no Tauri, no DOM), fully unit-testable

### 4.1 New file `src/generator/apiSource.ts`

| Function | Purpose |
|---|---|
| `urlVariables(url): string[]` | Unique variable names, in order of appearance. |
| `normalizeUrl(url): string` | Adds `https://` when no scheme is given. |
| `buildUrl(url, values): string` | Substitutes with `encodeURIComponent`; throws naming the first missing value. |
| `checkSourceUrl(url): string[]` | Problems: bad variable names, scheme other than http/https, `user:pass@` in the URL, empty host. |
| `readPath(record, path): unknown` | Walks `a.b[2].c`; throws a readable error when a step is missing. |
| `extractRecords(json, listPath?): unknown[]` | Array becomes records; object becomes `[object]`; with `listPath`, follows it first. Throws on empty or wrong type. |
| `toText(value, path): string` | Section 3.2 rules. |

### 4.2 Engine changes (`engine.ts`)

1. `Page` gains `record?: unknown`.
2. `evaluate()` gets `case 'api'`: `toText(readPath(page.record, rule.path), rule.path)`. With no record it throws "this field needs data from the API".
3. **New function**

   ```ts
   export function generateRowsFromRecords(
     spec: GeneratorSpec,
     records: unknown[],
     copies: number,
     opts?: GenerateOptions,
   ): Record<string, string>[]
   ```

    - Validates the spec, then checks `records.length * copies <= LIMITS.maxRows` **before** generating, with a message like "12,000 pages would be printed (1,200 records x 10 copies); the limit is 10,000."
    - Loops records, then copies (record-major, section 1). `page.index` counts total pages, so `sequence` rules keep counting up across the whole job.
4. `generateRows(spec, count)` stays as is for labels with no `source`. If the spec has `api` rules, it throws "This label needs API data" so no caller can print `undefined`.
5. Preview support: `GenerateOptions` gets `placeholders?: boolean`. When true, an `api` rule with no record returns `‹path›` instead of throwing. Used only by the editor sample and the preview dialog.
6. `validateSpec` additions:
    - `api` rule: `path` must be non-empty and syntactically valid.
    - Any `api` rule present but no `source`: "Field X reads the API but this label has no URL."
    - `source` present: run `checkSourceUrl`; `listPath` syntax check.
    - `source` present but no `api` field: allowed (valid), the Source pane just shows a hint.
7. `LIMITS` gains `maxResponseBytes = 5 * 1024 * 1024` and `fetchTimeoutMs = 15_000`.

### 4.3 Other pure files

- `scaffold.ts`: `scaffoldSpec` / `orphanRules` must preserve `source` and `api` rules (check the copy of `base`). No new field defaults; a new field still gets its existing default rule.
- `bundle.ts`: no logic change. `parseBundle` already runs `validateSpec`, which now covers `source`. Add tests that a bundle containing `source` round-trips and that the type has **no place for a token**.
- Importing a label that uses `api` into an **older** app version shows "unknown rule" and refuses the import. That is the existing behaviour for unknown rule kinds and is acceptable; note it in RELEASE.md.

## 5. HTTP transport

### 5.1 Why this needs care

- A plain `fetch()` in the webview is subject to **CORS**. A bearer token also triggers a CORS preflight. Many APIs would fail even though the same call works from curl.
- The Rust side has `ureq` without TLS, so HTTPS from Rust does not work today.

### 5.2 Options

| Option | Pros | Cons |
|---|---|---|
| A. Webview `fetch` only | Zero native changes | CORS breaks many APIs; unusable for non-CORS servers |
| B. `tauri-plugin-http` | Official, `fetch`-like API, no CORS | New dependency (reqwest + rustls), needs a capability scoped to `https://*`, larger APK |
| **C. Own Rust command `fetch_json` using `ureq` with its `tls` feature (recommended)** | Reuses the HTTP crate already in the project, small and auditable, size cap / timeout / redirect rules in one place, token stays in Rust | Enabling TLS pulls in `rustls` + `ring`, which compiles C code in the Android NDK build |

**Recommendation: C**, subject to the Phase 0 spike. If the Android build or APK size is a problem, fall back to B, then A (with a clear "this server blocks browsers" message).

### 5.3 Rust command (`src-tauri/src/http.rs`, registered in `lib.rs`)

```rust
#[tauri::command]
async fn fetch_json(url: String, bearer: Option<String>) -> Result<String, String>
```

- Runs in `spawn_blocking` (ureq is synchronous).
- GET only; `Accept: application/json`; `Authorization: Bearer ...` only when a token is given.
- Allowed schemes: `https`, `http`. **Refuses to send a bearer token over plain `http://`** ("Refusing to send a token without HTTPS.").
- Timeout 15 s; reads at most 5 MB, then errors "Response is larger than 5 MB".
- Redirects: follow only to the **same host**, and the `Authorization` header is dropped on any redirect. Otherwise error.
- Errors returned as plain text: network error, `HTTP 401 Unauthorized` plus the first 200 characters of the body, "not JSON". **The token never appears in any error, log or report.**
- Android: `http://` needs cleartext permission in the WebView, but this request goes from Rust, so it is not affected. Keep `http://` allowed for LAN APIs.

### 5.4 TypeScript client (`src/apiClient.ts`)

```ts
export async function fetchRecords(source: ApiSource, values: Record<string,string>, token?: string): Promise<unknown[]>
```

1. `buildUrl(normalizeUrl(source.url), values)`.
2. If `isTauri()`: `invoke('fetch_json', { url, bearer })`. Otherwise (browser dev / Designer test in web mode): `fetch(url, { headers })` with an `AbortController` timeout, and a CORS-specific error hint.
3. `JSON.parse`, then `extractRecords(json, source.listPath)`.

## 6. Print flow

### 6.1 `printApi.printLabels`

Add an optional `api?: { values: Record<string,string>; token?: string }` parameter.

```ts
const { template, source, generator } = await loadLabel(...);
let rows;
if (generator.source) {
  if (!opts.api) throw new Error('This label needs values for its URL.');
  const records = await fetchRecords(generator.source, opts.api.values, opts.api.token);
  rows = generateRowsFromRecords(generator, records, opts.pages);
} else {
  rows = generateRows(generator, opts.pages);
}
```

Required follow-up edits (easy to miss):

- Replace `opts.pages > RAW_THRESHOLD_PAGES` with **`rows.length > RAW_THRESHOLD_PAGES`**. Otherwise a 1-copy print of 500 records would be sent through the slow JSON-array path.
- `Timings` gets a `fetch` number; return `pageCount: rows.length` and `records: n` so the UI can report the real total.

### 6.2 `PrintPage.tsx`

When the selected label has `generator.source`:

- Show a **Data source** card under the label picker:
    - The URL with variable inputs: one text input per variable (label from `variables[x].label`, default from `variables[x].default`, remembered per label and user in `localStorage`, same style as `rememberLabel`). Inputs are required.
    - The **resolved URL** shown read-only below, with the host in bold. This matters for labels imported from someone else: the user can see where the app is about to send a request.
    - If `bearerAuth`: a password input "Access token" (`autoComplete="off"`), kept in React state only and cleared when the label changes.
    - A **Check data** button: fetches and shows "12 records found" plus the first record as formatted JSON. It is optional; Print works without it.
- Relabel the page-count field: "Copies of each record", hint "An object response counts as one record." Show the live total after a check: "12 records x 3 = 36 pages".
- `onPrint` passes `api: { values, token }`. Validation errors (missing variable, missing token) show before any request is made.
- Result panel: "Printed 36 pages (12 records x 3 copies)", and the timing breakdown gets a "Fetch" row.
- Existing `setResult({ pages })` must use the real total, not the page-count field.
- Abort: changing label or unmounting ignores a late response (a `stale` flag as in the existing resolutions effect).

## 7. Designer UI

### 7.1 `DataEditor.tsx`: a third pane, "Source"

Tabs become Fields | Tables | **Source**.

- **URL pattern** input with the detected variables shown as chips. Inline validation from `checkSourceUrl`.
- **List path** (optional) with a one-line explanation: "If the response is `{ "data": [ ... ] }` enter `data`."
- Per detected variable: optional label and default.
- **Use bearer token** checkbox, with the note "The token is asked for when printing. It is not saved in the label or in exported files."
- **Test** area: a value input per variable (and a token input), a **Fetch sample** button. On success it shows the first record as JSON and the list of leaf paths found in it. The sample lives in component state only (never saved). The token is not kept after the fetch.

- Rule form: a path text input with a `<datalist>` of the sample's leaf paths (if a sample was fetched), plus the existing prefix/suffix/transforms.
- Live sample text next to the field: with a fetched sample show the real value, otherwise `‹path›`.

### 7.3 `PreviewDialog.tsx`

Use `generateRows(spec, 3, { placeholders: true })` when there is no sample, or `generateRowsFromRecords` with the sample records (first three) when there is one.

### 7.4 `DesignerPage.tsx`

The existing save check already blocks on `validateSpec`, so the new rules apply with no extra work. The dirty-tracking (`JSON.stringify(generator)`) also covers `source` automatically.

## 10. Security and privacy

- The token is held in memory only, sent only in the `Authorization` header of that request, and is excluded from errors, logs, `PrintReport`, exports and the DB. The type system has no field for it in `ApiSource`.
- The token is refused over `http://` and dropped on redirects.
- Imported labels can contain a URL, so the print form always shows the resolved URL and host before sending anything.
- Variable values are URL-encoded so a value like `x/../../admin` cannot change the path.
- Response size, time and page-count limits stop a bad API from hanging or flooding a print job.
- Not stored: variable values are not secret, so remembering them per label in `localStorage` is fine. "Remember the token on this device" is deliberately **not** in v1 (would need secure storage).

## 11. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| `rustls`/`ring` fails or bloats the Android build | Blocks option C | Phase 0 spike first; fall back to `tauri-plugin-http` or webview `fetch` |
| API response shape differs between calls (field sometimes missing) | A print aborts midway in the user's eyes | Fail **before** generating the PDF, naming record number and path |
| Large arrays x copies | Slow PDF, memory | Total-page limit (10,000), raw-binary path chosen by `rows.length` |
| CORS in web mode | Designer test fetch fails in a browser | Only matters for dev; clear error text; Tauri build is unaffected |
| Older app versions cannot open new labels | Import refused | Document in RELEASE.md |
| User expects copies of one record to be identical including random fields | Surprise | Document; offer later option to freeze other rules per record |

## 12. Out of scope for v1 (possible follow-ups)

- POST bodies, custom headers, basic auth, OAuth flows.
- Pagination (`next` links / page numbers).
- Remembering the token (needs OS keychain / Android Keystore).
- Dragging a JSON key from the sample into a field.
- Other response formats (CSV, XML).
- Per-record copy counts read from a field in the response.
